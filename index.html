01DevOpsSep 2026MTS internship

Student Manager: CI/CD & Docker Deployment

The end of my DevOps internship at MTS: a Spring Boot student manager that travels from git push to a running container on an Ubuntu VM with nobody touching the server in between.

  • A GitLab pipeline that builds, tests, packages and deploys, run by a GitLab Runner I configured on Ubuntu with the shell executor.
  • A multi-stage Dockerfile: Maven builds the JAR in a JDK image, a slim JRE image runs it as a non-root user. The image goes to Docker Hub using CI/CD variables for the login.
  • The app and PostgreSQL as separate containers on their own Docker network, with a named volume so the data outlives every redeploy.
  • Debugged along the way: PostgreSQL connectivity, Docker networking, port mapping and VirtualBox networking.

    02SecurityJun 2026Team of 2

    AES-128 Encryption Simulator

    AES usually hides behind a library call. For our Data Security course we wrote it from the raw specification — no crypto libraries — and built a GUI that shows the 4×4 state after every single step.

    • SubBytes, ShiftRows, MixColumns over GF(2⁸) and AddRoundKey, all written by hand.
    • The full key schedule: 11 round keys, with RotWord, SubWord, Rcon and the g-function shown step by step.
    • A Tkinter interface that traces the state through any round you pick.
    • Python
    • Tkinter
    • GF(2⁸) arithmetic
    • No crypto libraries

    03EmbeddedJun 2026Team of 3

    RFID Access Control System

    A door lock split across two processors. An Arduino with an MFRC522 reads each card over SPI and makes the decision; an AT89C51 does everything you can see and hear, driven by a single byte over a 9600-baud serial link.

    • Card UIDs checked against EEPROM, with the first four cards auto-enrolled so the lock remembers them across power cycles.
    • 8051 assembly for the LCD driver, the servo's PWM timing and the LED and buzzer logic.
    • The whole circuit designed and simulated in Proteus before any hardware was assembled.

    04Artificial intelligenceOct 2026

    CyberClash AI

    A two-player, zero-sum strategy game on a ten-host network. The attacker starts at H0 and tries to reach the database on H5 and exfiltrate it; the defender patches, isolates and restores hosts on a budget of 10.

    • Full Minimax, depth-limited Minimax and Alpha-Beta pruning over one shared game model.
    • Benchmarks of expanded nodes, timing and memory from depth 1 to 5, showing how much pruning saves.
    • Unit tests for the rules and for both searches agreeing, plus a PySide6 GUI to play against the AI.
